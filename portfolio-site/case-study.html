CASE STUDY · 2026

Happy Hour Finder

Designing a discovery product where the hardest part is not finding deals—it's knowing when to trust them.

RoleProduct + Engineering
ScopeMobile, Web, Backend, Data
LocationChicago, IL
StackExpo · TypeScript · Supabase
01
THE PROBLEM

Happy hour information is useful only when people can trust it.

Restaurant specials are fragmented across menus, websites, social posts, and changing schedules. A discovery app can make the experience feel simple while hiding a difficult data problem underneath.

The product goal became broader than “show nearby deals.” It needed to help someone answer: What is happening, where is it, when does it end, and how confident should I be that this is still true?

02 / PRODUCT

A discovery loop built around action.

The core experience moves from discovery → filtering → deal detail → visit. Daily highlights surface trending, newly added, and ending-soon deals, while Explore supports neighbourhood, deal type, price, and time-of-day filters.

01ExploreServer-side full-text search and real filters.
02DecideDeal schedules, confidence states, and venue details.
03VisitCheck-ins, points, badges, and visit history.
04ContributePhoto-based deal submission with user correction.
03
DATA + AUTOMATION

Automation with a safety valve.

The content pipeline uses n8n to discover and validate deal information. OCR + LLM extraction can turn a photographed menu board into structured data, but extraction is never allowed to write directly to the catalogue.

0.80
Confidence threshold

Deals publish only when extraction confidence reaches the configured threshold and the time window passes the same parsing rules used by the app.

HUMAN
Review queue

Low-confidence or ambiguous records are routed for review rather than silently published. A low-confidence reading cannot overwrite a higher-confidence record.

04
ARCHITECTURE

Keep the client thin. Put trust where the data lives.

Supabase
Postgres · Auth · RLS

Every network read/write goes through the services layer. Database authorization is enforced with Row Level Security, while privileged actions use narrowly scoped server-side functions rather than broad client permissions.

This structure makes the app easier to test and keeps business-critical rules out of the UI.

05
ENGINEERING QUALITY

Build quality into the project, not at the end.

967tests across 49 suites
20SQL migrations
14RLS policies
213accessibility props

The test strategy isolates screen behaviour in hooks so most logic can be tested without rendering native maps or camera flows. The app also includes cached reads, network-state feedback, skeleton loading, error boundaries, and explicit configuration-error states.

06 / THE PRODUCT

From discovery to detail.

07 / TAKEAWAY

The product lesson: automate the work, not the judgment.

Happy Hour Finder started as a local discovery idea and became a systems-design exercise: how do you combine messy external information, automation, user-generated data, security, and a consumer interface without making the user absorb the complexity?
