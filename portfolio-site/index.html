02 / HOW I THINK
01

Start with the real problem

A polished interface is not enough. I look for the operational constraint underneath the user request and design around it.

02

Make data trustworthy

Automation should reduce work without quietly creating bad data. Validation, confidence, and human review belong in the architecture.

03

Build for change

I prefer clear service boundaries, testable logic, and systems that can evolve without rewriting the whole product.
