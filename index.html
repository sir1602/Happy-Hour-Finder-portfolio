Featured project

Happy Hour Finder

A cross-platform app for finding happy hours happening now, comparing deals, and picking a place to meet after work.

The map is the easy part. The hard part is the data: deals change, sources disagree, and one wrong listing makes people stop trusting the app. So I designed the whole system around that.

  • n8n pipeline that discovers, re-checks, and scores deals nightly
  • Publish gate: confidence ≥ 0.80, or it waits for a human
  • Postgres with Row Level Security; 967 tests in CI
  • Expo
  • React Native
  • TypeScript
  • Supabase

03 / How I think

How I think

01

Start with the real problem

A polished interface is not enough. I look for the operational constraint underneath the request and design around it.

02

Make data trustworthy

Automation should reduce work without quietly creating bad data. Validation, confidence scores, and human review belong in the architecture.

03

Build for change

Clear service boundaries, testable logic, and rules enforced where the data lives, so the system can grow without a rewrite.
